# M7 Known System Limitations and Future Roadmap

## Production Incident Intelligence System (PIIS — Telecom Edition)
**Milestone:** M7 Portfolio Edition (Release Candidate v1.0.0-rc2)  
**Standard:** Transparent Disclosure of Operational Boundaries and Technical Debt  
**Operational Scope:** Strictly Read-Only Decision Support

---

## 1. Transparent Disclosure of Known System Limitations

PIIS has been verified in an isolated, reproducible local environment as a portfolio and research release. The following technical, operational, and environmental limitations are explicitly acknowledged:

### 1.1. Synthetic Data & Simulation Fidelity
- **Observation vs Reality:** The telemetry, alarms, and ITSM tickets used during verification were generated by high-fidelity local simulators (`SimulatedITSMPlatform`, `SimulatedAlarmBroker`, `SimulatedTelemetryPlatform`) and synthetic datasets.
- **Limitation:** While simulated distributions model real 3GPP and vendor specifications (Nokia/Ericsson VSWR thresholds, GTP-U drop rates), they cannot fully capture the chaotic, multi-chassis transient failure cascades characteristic of tier-1 carrier live production networks.

### 1.2. Enterprise Infrastructure Absence (Local Standalone Testbed)
- **Local Equivalents:** Because the developer has no enterprise subscription to corporate cloud services, PIIS implements local standalone equivalents:
  - Corporate OIDC IdP $\rightarrow$ `LocalTestOIDCProvider` with RFC 8414 discovery and dynamic JWKS.
  - AWS/GCP KMS/HSM $\rightarrow$ `LocalDevKeyProvider` with ephemeral memory/file key material.
  - Enterprise RFC 3161 TSA $\rightarrow$ `LocalUtcTimestampProvider` / simulated TSA.
  - Enterprise WORM / S3 Object Lock $\rightarrow$ `FileBasedCheckpointAnchor` with monotonic rollback detection.
- **Limitation:** The local abstractions prove mathematical and algorithmic correctness, but do not satisfy corporate compliance certifications (SOC 2, ISO 27001) until bound to physical enterprise KMS/HSM and trusted TSAs.

### 1.3. Decision Support Boundary (No Autonomous Action)
- **Hard-Locked Policy:** PIIS is strictly a decision-support platform. It cannot execute router commands, restart gNodeBs, mutate BGP routing tables, or close ITSM tickets.
- **Operator Dependency:** A human NOC engineer must review every recommendation and manually execute operational procedures through authorized OSS/ITSM tools.

### 1.4. Network Domain Coverage
- **Covered Domains:** 5G/4G Radio Access Network (RAN), 5G Core (UPF/AMF session handling), and IP/Optical Backhaul Transport.
- **Uncovered Domains:** Legacy 2G/3G circuit-switched networks, satellite LEO constellations, submarine cable systems, and fixed-line broadband DOCSIS networks.

### 1.5. Local Single-Node Scaling
- **Throughput Boundary:** The in-memory pipeline processes ~550–1,100 events/second per core on bare metal.
- **Limitation:** The current release operates as a modular monolith running in a single Python process. Large-scale carrier deployments ingesting >50,000 alarms/second require distributed message brokers (Kafka/Flink) and horizontal partitioning.

### 1.6. Language & Internationalization
- **Current Support:** English-only error logs, runbook documentation, and UI microcopy.

## 2. Prioritized Roadmap for Future Work (Milestone M8 & Beyond)

| Horizon | Initiative | Architectural Objective |
| :--- | :--- | :--- |
| **Phase 1 (M8)** | **O-RAN Alliance Testbed Integration** | Deploy PIIS against open-source O-RAN Near-RT RIC (RAN Intelligent Controller) and E2 nodes to evaluate performance against physical software-defined radio hardware. |
| **Phase 2 (M8)** | **Cloud KMS & Hardware HSM Binding** | Bind `ExternalKMSProvider` to AWS KMS, Azure Key Vault, or PKCS#11 hardware security modules for FIPS 140-3 cryptographic sealing. |
| **Phase 3 (M8)** | **RFC 3161 Public TSA Integration** | Connect `RFC3161TimestampProvider` to public or enterprise Time Stamping Authorities (e.g. DigiCert, Sectigo) via HTTP/TSP. |
| **Phase 4 (M9)** | **Distributed Ledger Consensus** | Extend the append-only audit trail with Raft or Byzantine Fault Tolerant (BFT) consensus across multi-region NOC instances. |
| **Phase 5 (M9)** | **Active Operator Feedback Learning** | Implement privacy-preserving active learning from operator review notes and rejections to continually refine RAG retrieval ranking without model drift. |
