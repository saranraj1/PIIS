# ADR-0007: Server-Side Token Verification, RBAC Enforcement, and Durable Audit Persistence

- **Status:** Accepted
- **Decision:** Replace in-memory reviewer identity assertions with verified claims generated exclusively by server-side token verifiers (`ReviewerTokenVerifier` ABC, `IsolatedTestTokenVerifier` for testing, and `ProductionOIDCVerifier` for production). Direct instantiation of `AuthenticatedReviewer` without verified claims is prohibited. Enforce strict role-based access control (RBAC): approvals of `HIGH_RISK_MANUAL` recommendations require `NOC_LEAD` or `SYSADMIN` roles. Eliminate hardcoded audit keys by reading `PIIS_AUDIT_HMAC_KEY` from the environment or secure secrets manager (rejecting keys under 32 bytes or default strings). Persist all audit log entries to an append-only JSONL durable ledger file with thread-safe `RLock` synchronization, and restore state across process restarts via `load_from_ledger()` with complete hash-chain and HMAC integrity re-verification.
- **Context:** The M5.1 independent revalidation identified `FIND-M5.1-001`, showing that reviewer identity was constructed client-side without cryptographic verification, `HIGH_RISK_MANUAL` actions lacked server-side permission checks, audit HMAC used an insecure default fallback key, and in-memory audit logs were lost across process restarts.
- **Consequences:** Guarantees cryptographically proven reviewer identity, strict separation of privileges, tamper-evident post-restart audit recovery, and zero hardcoded secret vulnerabilities across testing and production environments.
