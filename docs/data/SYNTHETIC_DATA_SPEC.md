## 1. Core Principles & Governance Guardrails

> [!CAUTION]
> **SYNTHETIC DATA MUST NEVER BE REPRESENTED AS REAL TELECOM MEASUREMENTS.**
> Every record generated by PIIS-TelcoBench is tagged immutably with `source_type="SYNTHETIC"`, a deterministic `scenario_family_id`, and a random `seed`.

### 1.1 Non-Negotiable Generation Rules
1. **Causal Coherence (Physics-First):**
   - Causal variables must be simulated *first* (e.g., path loss, hardware failure, buffer saturation), and observable metrics (RSRP, BLER, throughput, packet drops), alarms, and ticket text must be derived directly from the physical failure mechanism.
2. **Lexical Independence (No Trivial Shortcuts):**
   - Ticket text must **NEVER** contain trivial verbatim label clues (e.g., writing *"This is an L2 RAN handover failure caused by X"* is strictly prohibited).
   - Ticket phrasing must vary organically using multi-template vocabularies and customer/NOC perspectives.
3. **Negative Controls & Ambiguity:**
   - At least 15% of generated scenarios must be **negative controls** (healthy baseline traffic fluctuations, temporary multi-path fading that self-resolves).
   - At least 10% of generated scenarios must be **ambiguous / under-specified** cases that correctly trigger `HUMAN_REVIEW` under the conservative routing policy.
4. **Leakage Prevention & Scenario-Family Holdout:**
   - Datasets are partitioned strictly by `scenario_family_id` and `split_group_id`. Models must never be trained and evaluated on variants from the same seed or scenario family.
5. **Reproducibility:**
   - Every run takes an explicit integer seed (e.g., `seed=42`). Re-running the generator with the identical seed produces bit-exact identical records, checksums, and timestamps.

## 2. Controlled Scenario Families (S01 — S10)

The 10 fundamental telecom production failure scenarios are defined below:

---

### S01 — RAN Signal Degradation
- **Domain:** Radio Access Network (4G / 5G RAN).
- **Causal Mechanism:** Antenna feeder line moisture ingress, remote radio unit (RRU) power amplifier gain drop, or physical antenna mis-alignment from high winds.
- **Observable Telemetry:**
  - `RSRP`: Drops steadily by 15 to 30 dBm (e.g., from -82 dBm down to -112 dBm).
  - `SNR`: Degrades from 18 dB down to < 2 dB.
  - `DL_BLER`: Climbs from < 1% up to 25–40%.
  - `DL_MCS`: Modulation downgrades from 256-QAM (MCS 26) to QPSK (MCS 2–4).
- **Alarm Sequence:**
  - `ALM-RAN-VSWR-01` (Antenna Voltage Standing Wave Ratio Out of Limits)
  - `ALM-RAN-PIM-02` (Passive Intermodulation Warning)
- **Support Tier Ground Truth:** `L2` (Physical/RF radio parameter diagnosis and tower climb required).
- **Ambiguous Variant:** Gradual fading during heavy rain that self-recovers (Negative control / no fault).

---

### S02 — Handover Failures
- **Domain:** Radio Access Network (RAN Mobility).
- **Causal Mechanism:** Missing Xn/X2 neighbor relation definition in target gNB or incorrect A3 event handover hysteresis offsets.
- **Observable Telemetry:**
  - `Handover_Success_Rate`: Drops from 99.2% down to < 65%.
  - `Radio_Link_Failures_HO`: Spikes 8x above historical baseline.
  - Target cell RSRP is high, but source cell drops bearer before transfer completes.
- **Alarm Sequence:**
  - `ALM-RAN-HO-EXC-FAIL` (Excessive Handover Preparation / Execution Failure)
- **Support Tier Ground Truth:**
  - If target cell neighbor relation is in documented automatic neighbor relation (ANR) SOP -> `L1`.
  - If boundary RF parameter recalculation is needed across vendor border -> `L2`.

---

### S03 — Cell Congestion
- **Domain:** Radio Access Network / Scheduler.
- **Causal Mechanism:** Massive sudden user influx (stadium event, traffic jam, festival) saturating Physical Downlink Shared Channel (PDSCH) PRB capacity.
- **Observable Telemetry:**
  - `PRB_Utilization_DL`: Sustained at 98–100%.
  - `Active_UE_Count`: Spikes from nominal 80 to > 600 UEs per sector.
  - `User_Perceived_Throughput`: Collapses from 120 Mbps to < 1.5 Mbps.
  - `DL_BLER`: Remains low (< 3%), proving clean RF channel but complete queuing saturation.
- **Alarm Sequence:**
  - `ALM-RAN-PRB-CONGEST` (High PRB Utilization Exceeds Major Threshold)
- **Support Tier Ground Truth:** `L1` (Standard load-balancing runbook: trigger intra-frequency traffic steering or enable cell admission control throttling).

---

### S04 — Base Station Outage
- **Domain:** Radio Access Network / Infrastructure.
- **Causal Mechanism:** Primary utility AC grid power failure combined with depleted site backup battery or optical fronthaul CPRI link disconnection.
- **Observable Telemetry:**
  - Complete telemetry flatline: 0 bytes/sec, 0 active users, cell operational status = `DOWN`.
- **Alarm Sequence:**
  - `ALM-PWR-MAINS-FAIL` (Site Mains Power Disconnected)
  - `ALM-PWR-BATT-LOW` (Backup Battery Voltage Critical)
  - `ALM-RAN-CELL-DOWN` (Cell Out of Service / No Transmission)
- **Support Tier Ground Truth:** `L1` (Verify power telemetry, dispatch site generator technician under standard facility SOP).

---

### S05 — Subscriber Authentication Failures
- **Domain:** 5G Core (5GC) / Security.
- **Causal Mechanism:** Security anchor function (SEAF) / Authentication Server Function (AUSF) certificate expiration or misconfigured home network private key in Unified Data Management (UDM).
- **Observable Telemetry:**
  - `5G_AKA_Auth_Success_Rate`: Plummets from 99.9% down to 0% for target IMSI ranges.
  - `HTTP2_SBI_Status_500` on AUSF service endpoint (`/nausf-auth/v1/ue-authentications`).
- **Alarm Sequence:**
  - `ALM-5GC-AUTH-TIMEOUT` (AUSF Signaling Response Timeout)
  - `ALM-5GC-UDM-CERT-ERR` (Mutual TLS Handshake Failed on SBI)
- **Support Tier Ground Truth:** `L2` (Core security certificate verification, PKI trust anchor update).

---

### S06 — PDU Session Establishment Failures
- **Domain:** 5G Core (Session Management).
- **Causal Mechanism:** Session Management Function (SMF) IP address pool exhaustion for a specific Data Network Name (DNN) / APN slice.
- **Observable Telemetry:**
  - `PDU_Establishment_Success_Rate`: Drops to 0% for new attach attempts.
  - Existing established PDU sessions remain active and passing traffic.
  - SMF logs indicate `INSUFFICIENT_UP_RESOURCES` or `IP_ALLOCATION_FAILURE`.
- **Alarm Sequence:**
  - `ALM-5GC-DNN-IP-POOL-EXHAUST` (SMF Subnet Capacity Limit Reached)
- **Support Tier Ground Truth:** `L1` (Approved runbook SOP-CORE-POOL: expand dynamic IP pool block or flush stale disconnected sessions).

---

### S07 — User-Plane Forwarding Degradation
- **Domain:** 5G Core User Plane (UPF) / Transport.
- **Causal Mechanism:** User Plane Function (UPF) DPDK ring buffer overflow or CPU core affinity pinning contention on virtualization host.
- **Observable Telemetry:**
  - Core control-plane (AMF/SMF) healthy and all PDU sessions established.
  - `UPF_Packet_Drop_Rate`: Spikes to 18–30%.
  - `N3_GTPU_Jitter`: Spikes from 2 ms to > 120 ms.
- **Alarm Sequence:**
  - `ALM-5GC-UPF-BUFFER-OVERFLOW` (GTP-U Ingress Buffer Saturation)
- **Support Tier Ground Truth:** `L2` (Virtualization host telemetry inspection, DPDK memory ring reconfiguration).

---

### S08 — Transport Link Degradation & Flapping
- **Domain:** Transport / Backhaul.
- **Causal Mechanism:** Microwave backhaul link alignment degradation due to thermal ducting or dirty optical fiber connector causing high bit-error rates on 10GE backhaul.
- **Observable Telemetry:**
  - Intermittent interface flapping (up/down state cycles every 90 seconds).
  - Round-trip ping latency jumps from 8 ms to 250 ms with 15% intermittent packet loss.
  - Radio cells report backhaul transmission delay alarms.
- **Alarm Sequence:**
  - `ALM-TX-PORT-FLAP` (Ethernet Port Carrier Flap)
  - `ALM-TX-CRC-ERR` (Excessive Optical Interface CRC Frame Errors)
- **Support Tier Ground Truth:** `L2` (Transport network engineering, OTDR optical loopback testing).

---

### S09 — DNS & Service Resolution Failures
- **Domain:** Core Service / IP Services.
- **Causal Mechanism:** DNS resolver pod cluster failure or misconfigured Gi-LAN DNS IP pushed in PDU session setup.
- **Observable Telemetry:**
  - Physical radio and 5G core bear 100% healthy signals.
  - Subscribers cannot resolve any external hostnames; high rate of ICMP Destination Port Unreachable for UDP port 53.
  - Massive spike in customer service calls reporting *"Connected without internet"*.
- **Alarm Sequence:**
  - `ALM-SRV-DNS-FAIL` (Primary Gi-LAN DNS Query Timeout)
- **Support Tier Ground Truth:** `L1` (Execute DNS resolver restart runbook SOP-SRV-004; verify fallback IP).

---

### S10 — Configuration Regressions
- **Domain:** Cross-Domain / Management.
- **Causal Mechanism:** Automated CI/CD or overnight maintenance script pushed mismatched MTU size (e.g. 1500 MTU pushed on gNB while transport enforces 1420 MTU).
- **Observable Telemetry:**
  - Signaling connects, small packets (pings, DNS) pass flawlessly.
  - Large TCP payloads (> 1420 bytes) hang indefinitely; zero throughput for HTTP/video streaming.
  - DF-bit (Don't Fragment) packet drops on edge router.
- **Alarm Sequence:**
  - `ALM-CFG-MISMATCH-MTU` (Detected MTU Path Inconsistency)
- **Support Tier Ground Truth:**
  - If standard post-change rollback script is documented -> `L1`.
  - If origin of configuration drift is unknown -> `L2`.

## 4. Controlled Generator Architecture & Interface

The scenario generator is implemented as a deterministic Python generator in `src/piis/synthetic/generator.py`:

```python
@dataclass
class ScenarioParameters:
    scenario_family: str       # S01 through S10, or S00
    seed: int                  # Explicit deterministic random seed
    variant_idx: int           # Variation sequence
    operator_policy: str       # Reference policy version
    include_ambiguity: bool    # Inject contradictory/missing telemetry
```

- **Output:** Fully conforms to `schemas/incident.schema.json`, `schemas/telemetry.schema.json`, and `schemas/alarm.schema.json`.
- **Reproducibility Guarantee:** Executing with `seed=42` produces bit-exact JSON/CSV records across all operating systems.
