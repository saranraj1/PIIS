# Data Governance, Provenance, and Privacy Framework

- **Document Version:** 1.1 (Updated Post Milestone 1)
- **Status:** Approved Engineering Baseline
- **Last Updated:** 2026-10-31

---

## 1. Provenance Classes

Every data record ingested, transformed, generated, or annotated within PIIS MUST carry one of the following five explicit provenance classifications:

1. **`PUBLIC_REAL`**: Obtained from an authorized public telecommunications dataset. Represents real-world physical network measurements or testbed observations as described by the publisher.
2. **`SYNTHETIC`**: Generated by the PIIS controlled scenario engine (`PIIS-TelcoBench`). Must never be presented as live operator evidence.
3. **`DERIVED`**: Computed, resampled, aggregated, or transformed from existing valid source records. Lineage to source record IDs must be retained.
4. **`HUMAN_ANNOTATED`**: Label, triage review, or correction supplied by a human engineer following the PIIS Annotation Handbook.
5. **`OPERATOR_INTERNAL`**: Ingested directly from an authorized telecom operator's internal production ITSM, OSS, or NMS systems under non-disclosure agreements.

---

## 2. Mandatory Provenance Metadata

All normalized canonical records must retain an immutable provenance block containing:
- `source_type`: One of the 5 canonical enum literals.
- `source_dataset`: Canonical dataset identifier or repository name.
- `source_record_id`: Precise row index, trace identifier, or original source record key.
- `original_timezone`: Logging timezone of the source system.
- `ingested_at`: UTC timestamp of transformation.
- `transformation_version`: Semantic version of the normalization pipeline.

---

## 3. Required Source Register Fields

Any new dataset incorporated into PIIS must be registered in `docs/data/SOURCE_REGISTER.csv` with:
`source_id,dataset_name,canonical_url,publisher,version,access_date,license_name,license_url,terms_checked_by,permitted_use,redistribution_allowed,file_path,sha256,file_size_bytes,row_count,schema_summary,known_limitations,notes`

---

## 4. Privacy, PII Protection, and Telecom Security

1. **Subscriber Identifiers Prohibited:**
   - Datasets must strictly omit or irreversibly hash subscriber personal data, including IMSI (International Mobile Subscriber Identity), IMEI (International Mobile Equipment Identity), MSISDN (phone numbers), and personal un-aggregated subscriber location trajectories.
2. **Operator Infrastructure Protection:**
   - Internal production IP addresses, element passwords, SNMP community strings, and network topology maps must be sanitized or replaced with synthetic token identifiers before ingestion.
3. **Target Leakage Prohibition:**
   - Post-resolution technician notes, confirmed root cause summaries, and post-prediction telemetry are strictly segregated from ticket-time prediction feature sets.
4. **Immutability of Raw Data:**
   - All files downloaded into `data/raw/<source_id>/` are write-protected and treated as read-only. No raw file may be altered in place.
5. **Retention and Deletion:**
   - Operator-specific data must comply with operator retention policies, GDPR, and regional telecom regulatory frameworks, supporting cryptographic erasure upon request.
